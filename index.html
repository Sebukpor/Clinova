The problem

Clinical information is everywhere. Usable clinical data is not.

Handwritten notes, scans, PDFs and free text carry the detail of a consultation, yet software can only act on data it can read and structure.

Existing applications often lack the means to extract text, structure findings, summarize encounters, normalize terminology or emit interoperable records. Clinova supplies those as separate API workflows. Your application decides what to show, review, store or act on.

What the API does

Six capability groups, each with its own endpoints.

Workflows are called separately, and outputs are designed for review by qualified staff.

Document intelligence & OCR

Extracts text from scans and PDFs, including multi-document requests. Persisted OCR can be retrieved and a reviewed version submitted back.

Input
Image, PDF (up to 50 pages), TXT
Processing
OCR
Output
Extracted text
POST /api/v1/ocr

Clinical extraction & summarization

Turns text or processed documents into typed entities, summaries and SOAP drafts, and flags documentation gaps. Translation is also available.

Input
Text or document
Processing
Extraction, summary, SOAP, gaps
Output
JSON in result
/entities · /summary · /soap · /gaps

Terminology & coding

Normalizes clinical terms, then looks up SNOMED CT and ICD-11 candidates. Candidates are suggestions for clinician or coder confirmation.

Input
Text or document
Processing
Normalization, code lookup
Output
Per-term candidate lists
/normalization · /snomed · /icd

Structured interoperability

Generates FHIR R4 resources from clinical content and validates them, so your pipeline can receive standards-shaped data.

Input
Text or document
Processing
FHIR R4 generation, validation
Output
Resource wrappers
POST /api/v1/fhir

Master-data matching

Matches OPD entities and pharmacy invoice items against candidate records you supply. Scored matches are returned, and accepted or corrected outcomes can be recorded.

Input
OPD text/documents or invoice items, plus your candidates
Processing
prepare, map, feedback
Output
Scored matches
/api/v1/hims-matching/…

Medication safety

Looks up drug interactions and adverse events and supports PRR/ROR-style safety-signal analysis for your pharmacists and prescribers.

Input
Drug, medication list or document
Processing
Interactions, safety signals
Output
Findings and risk assessment
/api/v1/pharmacovigilance/…

How it works

One integration path, five steps.

Your environmentClinova APIYour environment
  1. 01Your applicationYour HIMS, EMR, clinical app or authorized client starts the workflow.
  2. 02REST API requestIt submits supported input to the appropriate Clinova endpoint.
  3. 03Clinova processingThe relevant documented clinical AI workflow runs.
  4. 04Structured responseClinova returns that endpoint's output as JSON.
  5. 05Your workflow continuesYour application presents it for review or uses it downstream.

FAQ
Common questions.

    
What is Clinova?
An API-only clinical AI inference service from DAS Medhub, built on the Penthus Clinical AI Engine, that processes clinical documents and text through supported workflows.

    
Is Clinova an HIS, HIMS, EMR or EHR?
No. It does not implement patient management, scheduling or billing. It is called by the software you already use.

    
How does it integrate with existing software?
Your application sends HTTP requests to the relevant endpoints and handles the JSON responses. Scope depends on your systems and is assessed during evaluation.

    
Which inputs are supported?
Direct text, images, PDFs (up to 50 pages), plain text files and multi-document requests.

    
Does every capability use the same endpoint?
No. Each workflow has its own endpoint, with a shared request envelope for the clinical workflows.

    
Does it return structured outputs and support FHIR R4?
Yes. Workflows return JSON, and /api/v1/fhir generates and validates FHIR R4 resources.

    
How can we evaluate it?
Request a technical demonstration below, then follow the evaluation steps.

    
What does an evaluation cover?
Your clinical documentation and integration requirements, the relevant workflows and their inputs and outputs, and your security, data-handling and deployment requirements, leading to an agreed demonstration or pilot.
